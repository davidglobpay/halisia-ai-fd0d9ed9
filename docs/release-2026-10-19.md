# HALISIA release 2026-10-19.1

Base/rollback revision: `eb60910a1a736fb21d6a1883af49b77032b7d038`, connected branch `codex/reconciled-release-20261015`.

## Changes

- Replaced obsolete CARTO raster URLs in the Passport, evidence preview, pin picker, county map, heatmap and fallback maps. Road tiles use OpenStreetMap; satellite imagery remains Esri. Labels on satellite use Esri reference tiles.
- Map decode/provider failures produce a clean unavailable panel instead of cancelling the Passport. Branding still has to load before downloading.
- Reserved room for captions and full evidence entries; enlarged amenity cards; removed footer logos while retaining exact header branding and watermark.
- Suppressed amenity points within five metres of the query centroid. This is a location-quality filter, not a claim that facilities are absent. Shared non-centroid coordinates are retained because facilities can be colocated. All-capital labels are formatted without correcting unverified spelling; short acronyms are preserved.
- Cover counts explicitly refer to populated evidence-directory entries; maps, amenities and charts are separate context.
- Added the returned 5×5 elevation samples to the terrain page, labelled by elevation and north orientation. No surveyed contours are invented.
- SoilGrids parser requires complete composition fractions and explicit units, normalizes depth labels, preserves optional missing carbon/density as null, and distinguishes provider failure from an empty sample.
- Removed the terrain-to-erosion, drainage, geology, bedrock, groundwater, bearing-capacity and foundation verdict mechanisms. Unsupported API values are null/empty, and missing terrain is null rather than a substituted 1000 m plane. Soil model composition and regional terrain readings remain. The separate geotechnical PDF now uses the same Passport renderer and clearly identifies required professional investigation.
- Captured privilege reductions in migration source and applied empty search paths on three already-qualified RPCs.
- Added private, anonymous intake burst counters and PostgreSQL log alerts. These are fail-open monitoring, **not enforced rate limits**; they do not discard enquiries or retain IP/contact identifiers. Retention is two days when new buckets are observed.
- Guarded lead, proposal, professional request and viewing decisions without expanding RLS permissions. Providers cannot accept their own proposals or rewrite accepted terms; buyers cannot confirm their own viewing. Status changes cannot rewrite identity/contact/request fields. Service-role authority remains.
- Report shares and versions must reference a saved item owned by their creator. Existing invalid parent count was zero before applying the constraints. Review tables have no third-party decision/verification field; no unnecessary review guard was added. Vault sharing already checked document ownership.

## Explicit blockers / follow-up

1. **Database owner:** run the following using a role authorized to change `supabase_admin` defaults. The connected `postgres` role returned SQLSTATE 42501, permission denied. No workaround was attempted. Current table grants were already clean; this is the future-table default path.

   ```sql
   ALTER DEFAULT PRIVILEGES FOR ROLE supabase_admin IN SCHEMA public
     REVOKE TRUNCATE, TRIGGER, REFERENCES ON TABLES FROM anon, authenticated;
   ```

2. **Backend/edge owner:** introduce a trusted caller identity and tested enforced rate limits. Monitoring alone does not stop spam. Preserve a visible retry response and fail-open on limiter infrastructure failure.
3. **Data integration owner:** SoilGrids bulk queries timed out; a single clay query succeeded. ISRIC documentation describes REST instability. Parser repairs cannot guarantee upstream availability. Evaluate a licensed/keyless ISRIC WCS/WebDAV or published raster adapter before claiming reliable soil coverage.
4. **QA:** signed-in hosted acceptance and actual Passport browser download remain. Never treat a 200, build marker, synthetic test, or source audit as proof of complete workflows.
5. **Payments/operations:** payments/subscriptions and live Scout dispatch stay disabled pending their operational tests. No billing changes or paid Lovable agent runs were used.
6. **Marketing:** publish a marketing deck only from verified features and current real screenshots; no new marketing artifact was produced in this release.

The application is not a registry integration, title authentication service, legal-access determination, land survey or structural design service.
